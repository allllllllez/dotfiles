# Bash Tool 実行規律

## 作業ディレクトリの明示

Bashツールの作業ディレクトリはコマンド間で持続する。複数のリポジトリ・ディレクトリを
跨いで作業するときは、各コマンドの先頭で対象ディレクトリへ明示的に `cd` する。
直前のコマンド呼び出しの `cwd` が残っている前提でコマンドを書かない。

複数のリポジトリに同種の操作（ブランチ作成、状態確認など）を連続して行うときは特に注意する。
1回でも「意図しないディレクトリで実行された」ことに気づいたら、その場の再実行だけで済ませず、
以降の同種コマンド全てに明示的な `cd` を付け直す。

## バックグラウンドタスクを sleep で待たない

`run_in_background` で起動したコマンドの完了を、`sleep N; tail <output>` で
待たない。完了すると通知が届いて自動的に再開するため、待ちは不要である。

`sleep` で待つと前景の Bash が数分間ブロックされ、その間 Cru からは何も
起きていないように見える。直前の出力が誤解を招く内容（permission denied など）
だった場合、Cru が不要な対処を始める。

起動したらそのターンを終える。次にやることがあるなら、待たずにそれを進める。

例外は、ハーネスが追跡できない外部の状態を待つときだけ（CI の実行、
デプロイの反映など）。その場合も、対象の状態が変わる速度に合わせた間隔を選ぶ。

## 権限で拒否されうるコマンド

サブエージェントの報告や同じセッションの過去の試行で拒否されたコマンドは、自分で再実行しない。
計画では、Cru に `! <command>` での実行を頼む案を第一案に置く。

パッケージのインストールなど、権限で拒否されうるコマンドは `&&` で他のコマンドと連結しない。
連結すると、どれが拒否されたのか切り分けられず、確認の往復が増える。

作業ディレクトリを変えるために `cd X && <コマンド>` と連結しない。
パッケージ管理コマンドは、`--prefix <絶対パス>` のようにディレクトリを引数で渡して単一のコマンドにする。
単一のコマンドで絶対パスを渡せるときは、先頭の `cd` を省いてよい。

複数の検証（構文チェック、一時ファイルの作成、テスト実行、後片付け）を1回の呼び出しにまとめない。
拒否されたときに、どの部分が原因かを切り分けられず、再試行の方針が立たない。目的ごとに呼び出しを分ける。

## Python の import 失敗

`python3 -I` は、ユーザーサイト（`pip install --user` の置き場）を読まない。
`-I` 付きで `ModuleNotFoundError` が出たときは、「入っていない」と判断する前に、次の 2 つで切り分ける。

- `-I` なしの `python3 -c "import <モジュール>"` が通るか
- `uv run --with <パッケージ> python3 -I <スクリプト>` が通るか

pip install の依頼は、2 つとも失敗してから出す。

## 実行場所の明示

`!` で渡すコマンドは、この Claude セッションの shell（ホスト）で動く。
コンテナ内のコマンドを頼むときは、どの環境で、どのプロンプトのターミナルで実行するかを1行目に書く。

`!` を使わないコマンドも同じ。Cru に実行を頼むコマンドブロックの直前に、
「実行場所：ホスト / devcontainer」と「リポジトリ」を1行で書く。
ホストと devcontainer では、作業ツリーのパスが異なる。
