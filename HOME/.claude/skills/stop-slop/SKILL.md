# stop-slop

## 概要

書いた文章を「AIが書いた感」から抜き出すためのチェックリストとスコアリング。除去対象は、論点を増やさず「ちゃんと書いている感」だけを付ける言い回しと、内容より演出を優先する構造パターン。

禁止フレーズ・Before/After、ダッシュ・中黒の禁止、決め台詞の演出抑制は [[writing-technical]] の「LLMっぽい表現の禁止」節と「整形」節・「演出の抑制」節がすでに担当している（記述は である調 だが、ですます調にも語尾を読み替えて適用する。読み替え方は後述）。ですます調の「枠を宣言する語には操作か中身を入れる」節は [[writing-structure]] が担当している。この skill はそれらを重複させず、文体を問わず使える統合チェックリストと、既存2つの rules がまだ拾っていない構造パターンだけを新規に扱う。

文章を見直すときは、まず既存2つの rules の点検リストを適用し、その後で以下の新規項目を確認する。

## 既存 rules が担当する項目（ここでは詳述しない）

- 予告と総括、正面から系、空虚な形容・空虚な動詞、接続の型の連打、弱い緩和の濫用、ダッシュ・中黒の禁止、決め台詞の演出抑制 → [[writing-technical]]
- 枠を宣言する語（「見る」「扱う」で済ませない）、書式と強調記号の上限 → [[writing-structure]]

ですます調の文章を対象にするときは、[[writing-technical]] の禁止フレーズ一覧を文体に合わせて読み替えて適用する（「〜と言えるだろう」なら「〜と言えるでしょう」）。この読み替えは語尾だけに及び、禁止の対象は変わらない。

## 書き換えの原則

検出した箇所を書き換えるときは、原文にある情報だけで書く。

- 原文にない事実（数値、機構、原因、エラーの出方、検知経路）を足さない。推測が混ざった一文は、推敲の成果物として出した時点で確認済みの記述として読まれる。
- 足さないと文が成立しない箇所は、書き換えずに `[要確認: 何を確認すべきか]` を残して著者に返す。
- 行為者を一般的な語（「担当者」「チーム」など）に補うのは認める（3節）。個人名や組織名を推測して補うのは認めない。

スロップの多くは、情報を比喩や演出で包んだ形で現れる。包みを外せば中身が出るので、たいていは書き換えだけで足りる。中身が空の箇所は、書き換えでは埋まらない。埋めるのは著者の仕事である。

以下の Before/After 例は、いずれも悪い例に含まれる情報だけで良い例を組み立てている。同じ制約で書き換える。

## 新規に扱う項目

以下8項目は文体を問わず適用する。例は である調 で示すが、ですます調でも同じ型を検出する。書き換えるときは元の文体を保つ。

### 1. 二項対立の芝居

「Aではない。Bだ。」のように、否定を演出として使い、Bを直接言う前に一度Aを立てて壊す構文。

悪い例：「原因は個人の能力不足ではない。仕組みの不備だ。」
良い例：「原因は仕組みの不備にある。」

否定してから言い直すこと自体は、根拠を示す限り誠実な譲歩として必要な場面もある（[[writing-technical]] の「AではなくBと否定するときは、否定の根拠を一文添える」が担当）。ここで禁止するのは、否定の根拠を示さずに対比の型だけを流用する演出。

### 2. 列挙的お立て台詞

「〜ではない。〜でもない。〜だ。」のように三段階否定してから答えを言う構文。答えを最初から言う。

悪い例：「これは仕様ではない。バグでもない。設計判断の結果だ。」
良い例：「これは設計判断の結果だ。」

### 3. 無生物主語の人間的動作

無生物や抽象概念を主語にして、人間の行為であるかのような動詞を使う構文。行為者を特定したくないときにこの構文へ逃げやすい。

悪い例：「議論がその場で解決策に姿を変えた。」
良い例：「議論を重ねて、その場でチームが解決策を決めた。」

行為者が本当に不特定なら、一般的な語（「チーム」「担当者」など）に置き換える。誰の行為でもない自然現象（「気温が上がった」など）は対象外。

### 4. 距離を置いた語り

個別の事実を、当事者から距離を置いた一般化文で処理する構文。「〜する人は多い」「〜が起こりがちだ」のように、誰の話かを曖昧にしたまま済ませる。

悪い例：「レビューで同じ箇所が3回続けて見落とされた。こうした見落としは起こりがちだ。」
良い例：「レビュー担当者が同じ箇所を3回続けて見落とした。」

統計的傾向として正しい一般論を述べる場合は対象外。個別の事実を一般化文に逃がしている場合だけを指す。

### 5. リズムの単調さ

文の長さが揃いすぎている構文。特に、同じ構文の短文を3つ以上連続させる。

悪い例：「レビューをした。指摘を書いた。修正を依頼した。」
良い例：「レビューをして指摘を書き、修正を依頼した。」

短文の連打自体が悪いわけではなく、単調さが悪い。長短を混ぜる。

### 6. 比喩名詞への逃避

位置や役割を、場所や物の比喩名詞で済ませる構文。「入口」「土台」「道具」「核心」「落とし穴」「別物」がこの型に入る。この6語は例示であり、閉じた集合ではない。「本質」「範囲」「境界」のような語も、関係を書かずに示したように見せているなら同じ型として扱う。

悪い例：「認証はセキュリティの入口であり、ここが設計の核心になる。認証を破られると、以降の権限チェックは参照されない。」
良い例：「認証を破られると以降の権限チェックは参照されないため、設計は認証から決める。」

比喩名詞は、何が何によって決まるのかを書かずに関係を示したように見せる。具体名詞か、関係を述べる一文に戻す。比喩を残すなら、対応関係を1文で明示する（[[writing-structure]] の「比喩は、力学が一致するものを選ぶ」が担当）。

### 7. 静かな破局の演出

障害や失敗を、劇的な語で修飾する構文。「静かに壊れる」「その瞬間」「ここが効く」「事故につながる」「黙って落ちる」がこの型に入る。

悪い例：「この設定を忘れると、キャッシュは黙って古い値を返し続け、ある瞬間に静かに壊れる。エラーログには出ない。」
良い例：「この設定を忘れると、キャッシュは古い値を返し続ける。エラーログには出ない。」

ですます調でも同じ型が出る。

悪い例：「移行の瞬間に、旧APIは黙って空配列を返すようになります。ステータスコードは200のままです。ここが事故の入口です。」
良い例：「移行後、旧APIは空配列を返します。ステータスコードは200のままなので、呼び出し側では失敗と区別できません。」

障害の記述には、起きる現象と、気付けない理由だけを書く。劇的な語を足しても情報は増えない。

### 8. 書式の膨張

太字、箇条書き、ダッシュ、「まとめ」見出しを、地の文で足りる箇所に使う構文。個々の使用が悪いのではなく、密度が上がりきった状態を疑う。

次の密度を超えたら、書式ではなく構成を見直す。

- 太字が1見出しあたり2箇所以上ある（[[writing-structure]] の上限は1箇所。書き換えの目標もこちらに合わせる）
- 箇条書きの項目が、地の文の段落と同じ長さになっている
- ダッシュ（`—` `―` `——`）が本文に1つ以上ある（[[writing-technical]] が全面禁止している）
- 末尾に「まとめ」見出しがあり、その中身が本文の言い換えだけである

箇条書きは、同じ種類で同じ粒度のものが並ぶときだけ使う。太字は、止めた位置の文が独立して読めるときだけ使う。いずれも [[writing-structure]] の規則に従う。

## 禁止しない語

次の語は、この skill の検出対象にしない。いずれも記述を具体にする方向の語であり、削ると「確認していないことを確認したかのように書く」側へ寄る。

実測、疑う、照合、突き合わせる、見落とす、切り分ける、潰す、既定。

AI が書いた文章でこれらの語の出現が増えているという観測はあるが、出現頻度と文章の質は別の指標である。頻度を根拠に削らない。

## Quick Checks

文章を書き終えたら、次を順に確認する。

- [ ] 二項対立の芝居（「AではなくB」の型で、根拠を示さず対比だけを演出していないか）
- [ ] 列挙的お立て台詞（否定を2つ以上重ねてから答えを言っていないか）
- [ ] 無生物主語が人間の行為を担っていないか
- [ ] 個別の事実を「〜する人は多い」で一般化して逃げていないか
- [ ] 同じ構文の短文が3つ以上連続していないか
- [ ] 「入口」「土台」「道具」「核心」「落とし穴」で関係を説明したことにしていないか
- [ ] 障害の記述に「静かに」「黙って」「その瞬間」「効く」を足していないか（障害や効果を劇的に修飾する用法に限る。「絞り込みが効かない」のような技術上の慣用は対象外）
- [ ] 太字が1見出しあたり2箇所以上ないか、箇条書きの項目が段落の長さになっていないか
- [ ] 末尾の「まとめ」が本文の言い換えだけになっていないか
- [ ] 書き換え後の文章に、原文にない事実（数値、機構、原因、エラーの出方）を足していないか
- [ ] [[writing-technical]] の禁止フレーズ一覧・ダッシュ・中黒の禁止に該当する語がないか（である調の場合）
- [ ] [[writing-structure]] の枠を宣言する語の禁止に該当していないか

## スコアリング

6軸で1〜10点、満点60点。採点対象は修正前の文章とする。42点は目安であり、文章の状態を一言で伝えるための要約に使う。

出力を分けるのは点数ではなく検出件数である。採点者ごとに数点動く値に成果物の種類を委ねない。

- 新規8項目の該当が1件以上あるとき: 指摘一覧と、書き換え後の文章を出す。
- 該当0件のとき: 書き換えを出さず、任意の指摘だけを添える。任意の指摘は、原文にない情報を足さずに書ける範囲で、どう直せるかを1文で示す。

| 観点 | 問い |
|---|---|
| 直接性 | 結論を最初に言っているか、演出のために遠回りしていないか |
| リズム | 文の長さが混ざっているか |
| 行為者の明示 | 誰がやったかが文から読み取れるか |
| 具体性 | 個別の事実で語っているか、一般化や比喩名詞で逃げていないか |
| 削れる語の有無 | 二項対立、三段否定、障害の劇的修飾が残っていないか |
| 書式の密度 | 太字・箇条書き・ダッシュ・「まとめ」が、地の文で足りる箇所に使われていないか |
